# 01. 其他项目的通用使用说明

## 1. 适用范围

该 Skill 可用于多数分阶段重构项目，例如：

- 单体应用拆分
- Web/CLI 收敛
- 数据库 Schema 重构
- API 版本迁移
- 前端信息架构重做
- Legacy 入口退役
- 测试体系和交付验收
- 多模块技术债清理

最适合存在以下特征的项目：

- 有 TaskList、Issue、RFC 或阶段性需求
- 改动跨多个模块
- 需要保留兼容和迁移路径
- 希望 GPT-5.5 负责决策，mini 负责确定性工程工作
- 需要控制上下文和高阶模型额度

## 2. 安装

在 ZIP 解压目录中，将以下内容复制到目标仓库根目录：

```text
.codex/
└── agents/
    ├── refactor-explorer-mini.toml
    └── refactor-executor-mini.toml

.agents/
└── skills/
    └── refactor-orchestrator/
```

如果项目没有 `.codex/config.toml`：

```bash
cp .codex/config.toml.example .codex/config.toml
```

如果已有配置，只合并：

```toml
[agents]
max_threads = 4
max_depth = 1
job_max_runtime_seconds = 1800
```

不要直接覆盖原配置。

验证安装：

```bash
bash .agents/skills/refactor-orchestrator/scripts/validate-install.sh
```

## 3. 启动主 Agent

从仓库根目录启动 GPT-5.5：

```bash
codex -m gpt-5.5
```

建议一个 Stage 使用一个新的主 Session，不要整个项目永久使用同一 Session。

## 4. 第一次使用 Prompt

项目已有 TaskList：

```text
Use the refactor-orchestrator skill.

Choose and explicitly spawn subagents according to the Skill rules.
Do not rely on implicit delegation.
Use the minimum viable number of agents.

Plan and execute <Stage ID> from:
<task-list-path>

Requirements:
1. Read repository instructions first.
2. Inspect the current repository before planning.
3. Use refactor_explorer_mini only for independent read-only investigations.
4. Freeze architecture and public contracts before spawning executors.
5. Delegate only bounded tasks to refactor_executor_mini.
6. Execute by dependency batch and wait for each batch.
7. Review the actual git diff and verification output.
8. Do not mark the stage complete until every exit criterion has evidence.
```

项目没有正式 TaskList：

```text
Use the refactor-orchestrator skill.

Choose and explicitly spawn subagents according to the Skill rules.
Do not rely on implicit delegation.
Use the minimum viable number of agents.

Create a staged implementation plan for this request:
<request>

First inspect the repository.
Define the current source-of-truth, target behavior, migration risks,
task dependencies, verification commands, and acceptance criteria.
Then delegate only bounded implementation tasks to mini subagents.
```

## 5. 推荐执行流程

```text
GPT-5.5 读取需求与代码
→ 按需调用 Explorer mini
→ GPT-5.5 冻结架构和契约
→ 生成 Task Cards
→ Executor mini 分批实现与测试
→ GPT-5.5 检查真实 diff
→ GPT-5.5 做语义 Review
→ Stage 验收
```

## 6. 什么时候使用 Explorer

适合：

- 不清楚真实调用链
- 需要全仓搜索旧入口
- 数据库、API、前端或任务系统存在重复实现
- 删除前需要确认引用
- 需要并行调查互不重叠的区域

不适合：

- 已明确只有 1～3 个文件
- 已有冻结接口
- 只是局部修复
- 主 Agent 直接读取即可完成

## 7. 什么时候使用 Executor

任务卡满足以下条件才启动：

- 一个明确目标
- 契约已经冻结
- 允许和禁止修改范围明确
- 依赖已经完成
- 测试命令明确
- 遇到冲突时有停止条件

不要向 Executor 只发送“完成这个 Stage”之类的宽泛指令。

## 8. 并行规则

可并行：

- 前端页面与独立后端测试
- 不同目录的文档和局部实现
- 多个只读调查
- 不共享公共契约的独立模块

必须串行：

```text
领域模型
→ 数据库 Migration
→ API Schema
→ 生成客户端或前端类型
→ 集成测试
```

当多个 Agent 可能改同一文件、同一表、同一 API 或同一状态存储时，不要并行。

## 9. Agent 如何同步

- 主 Agent 将任务卡、契约和路径显式传给子 Agent。
- 子 Agent 通过共享工作区产生代码变化。
- 子 Agent 返回结构化结果。
- 依赖任务通过 handoff 文件和父 Agent 指令交接。
- 主 Agent 使用 `git status`、`git diff` 和测试结果复核。

子 Agent 不会自动继承主 Agent 的完整思考过程，因此关键决策必须写入任务卡或契约文件。

## 10. 状态目录

初始化：

```bash
bash .agents/skills/refactor-orchestrator/scripts/init-refactor-state.sh stage-1
```

默认生成：

```text
.codex/refactor-state/stage-1/
├── stage-plan.md
├── manifest.yaml
├── contracts/
├── tasks/
├── handoffs/
└── reviews/
```

临时执行记录可以不提交 Git；需要长期审计时再移动到项目正式 docs 目录。

## 11. Review Prompt

```text
Use the refactor-orchestrator skill.

Review the current stage using:
- source requirement
- stage plan and approved contracts
- task cards and handoffs
- current git diff
- actual verification results

Classify findings as BLOCKER, HIGH, MEDIUM, or LOW.
Check behavior, contract consistency, migration, rollback,
source-of-truth uniqueness, traceability, and scope drift.
Do not accept the stage only because subagents reported success.
```

## 12. Token 控制建议

- 每批 1～3 个 Executor。
- 不要为小任务创建 Explorer。
- 将实现、测试和机械自检合并给同一个 Executor。
- 不向子 Agent 发送整个仓库历史。
- 只传当前 Task 必需文档和上游 handoff。
- 长 Stage 的 Review 可新开独立 GPT-5.5 Session。


## 权限与运行时间注意事项

- `refactor-explorer-mini.toml` 中的 `sandbox_mode = "read-only"` 是默认配置。
  父 Session 的运行时权限覆盖可能优先于 Custom Agent 配置，因此严格只读调查时，
  不要使用 unrestricted full-access/yolo 模式启动父 Session，并在 spawn 后确认实际权限。
- `job_max_runtime_seconds` 主要用于批量 worker 的默认运行时间控制，
  不应把它当作所有普通 subagent 的统一强制超时。
- 仓库必须处于 trusted 状态，否则项目级 `.codex/` 配置可能不会被加载。


## 13. 新增的可靠性机制

### 最小 Lane 原则

默认规则：

```text
已知的局部任务：0 个 Explorer + 1 个 Executor
未知的跨模块任务：1～3 个 Explorer，之后默认 1 个 Executor
只有路径和公共契约不重叠时才并行 Executor
```

### 运行时探测

首次使用或 Codex 升级后运行：

```bash
bash .agents/skills/refactor-orchestrator/scripts/runtime-probe.sh
```

静态 TOML 不能证明实际使用了指定模型。仍需在 Session 中确认：

- 主模型为 GPT-5.5
- Skill 和 Custom Agents 已被发现
- native subagents 可用
- 子 Agent 实际使用 GPT-5.4 mini
- Explorer 实际权限为只读

### 修复轮次上限

同一 Task 最多三轮：

```text
第 1 轮：实现
第 2 轮：定向修复
第 3 轮：最终受限修复
```

三轮后仍失败则停止并升级给 GPT-5.5 或用户，避免无限消耗额度。

### 每轮产物

```bash
bash .agents/skills/refactor-orchestrator/scripts/capture-round-artifacts.sh TASK_ID ROUND
```

保存 diff、测试日志、状态、结果和 Review。

### 单控制器回退

native subagents 不可用或模型无法验证时：

- GPT-5.5 保持唯一控制器
- 继续生成 Plan、契约和 Task Card
- 输出手动启动 mini Session 的命令
- 不得声称已经调用 mini subagent


## 显式创建 Subagents

每个 Stage 的启动 Prompt 建议明确包含：

```text
Choose and explicitly spawn subagents according to the Skill rules.
Do not rely on implicit delegation.
Use the minimum viable number of agents.
```

这表示：

- 需要委派时，主 Agent 必须显式创建已配置的 Custom Agent；
- 不能只在计划中建议“可以使用 subagent”；
- 不要求每次都创建 subagent，小型局部任务的最小 Agent 数量可以为 0。

中文等价写法：

```text
按照 Skill 中的委派规则显式创建已配置的 subagents，
不要依赖隐式委派，并使用完成任务所需的最少 Agent 数量。
```
