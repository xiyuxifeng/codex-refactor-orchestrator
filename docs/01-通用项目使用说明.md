# Codex Refactor Orchestrator 通用使用说明

本说明面向第一次使用 Codex Skill 和 subagents 的用户。

# Part A：快速开始

## 1. 它是怎么工作的？

```text
GPT-5.5 主 Agent
├── 可选：refactor-explorer-mini
├── refactor-executor-mini
└── GPT-5.5 Review 与 Stage 验收
```

职责划分：

- GPT-5.5：理解需求、检查仓库、决定架构、冻结契约、Review 和验收。
- Explorer mini：只读调查调用链、旧入口、数据源、测试和引用。
- Executor mini：在边界明确后实现代码、补测试、运行 lint/typecheck，并返回交接结果。

## 2. 安装

从本项目目录运行：

```bash
./install.sh /path/to/your-project
```

目标项目会新增：

```text
.agents/
└── skills/
    └── refactor-orchestrator/

.codex/
├── agents/
│   ├── refactor-explorer-mini.toml
│   └── refactor-executor-mini.toml
└── config.toml
```

如果目标项目已有 `.codex/config.toml`，安装脚本会保留原文件。你需要手工确认其中包含：

```toml
[agents]
max_threads = 4
max_depth = 1
job_max_runtime_seconds = 1800
```

## 3. 验证

进入目标项目根目录：

```bash
cd /path/to/your-project

bash .agents/skills/refactor-orchestrator/scripts/validate-install.sh
bash .agents/skills/refactor-orchestrator/scripts/runtime-probe.sh
```

两个脚本的区别：

- `validate-install.sh`：检查 Skill、Agent TOML 和安装路径。
- `runtime-probe.sh`：检查当前 Codex 环境是否具备运行条件。

注意：静态配置正确，不代表运行中的子 Agent 一定使用了 GPT-5.4 mini。仍需在 Codex 中查看实际 Agent 信息。

## 4. 启动主 Session

```bash
codex -m gpt-5.5
```

建议一个 Stage 使用一个新的主 Session。

## 5. 第一次使用 Prompt

### 已有 TaskList

```text
Use the refactor-orchestrator skill.

Choose and explicitly spawn subagents according to the Skill rules.
Do not rely on implicit delegation.
Use the minimum viable number of agents.

Plan and execute <Stage ID> from:
<task-list-path>

Requirements:
1. Read repository instructions first.
2. Inspect the current repository before planning.
3. Freeze architecture and public contracts before spawning executors.
4. Delegate only bounded tasks to refactor_executor_mini.
5. Execute by dependency batch and wait for each batch.
6. Preserve the required diff, test, result, and review artifacts.
7. Review the actual git diff and verification output.
8. Do not mark the Stage complete until every exit criterion has evidence.
```

示例：

```text
Plan and execute Stage 2 from:
docs/Refactor-TaskList.md
```

### 没有 TaskList

```text
Use the refactor-orchestrator skill.

Choose and explicitly spawn subagents according to the Skill rules.
Do not rely on implicit delegation.
Use the minimum viable number of agents.

Create a staged implementation plan for this request:
<your request>

Inspect the repository first.
Define the current source-of-truth, target behavior, risks,
task dependencies, verification commands, and acceptance criteria.
Then delegate only bounded implementation tasks to mini subagents.
```

## 6. Skill 会自动处理什么？

主 Agent 应自动完成：

1. 读取仓库规则和需求；
2. 检查当前实现；
3. 判断是否需要 Explorer；
4. 冻结架构、接口和数据契约；
5. 生成 Task Card；
6. 显式创建 mini subagent；
7. 按依赖批次执行；
8. 保存每轮 diff 和测试证据；
9. GPT-5.5 Review；
10. Stage 验收。

你不需要每次手工决定使用 Explorer 还是 Executor。

## 7. 你需要处理什么？

只有这些情况通常需要你介入：

- TaskList 和现有实现存在产品方向冲突；
- 需要在两个业务方案中做取舍；
- 数据迁移可能丢失信息；
- Stage 验收失败且原因不是简单代码错误；
- native subagent 或实际模型无法验证；
- Agent 请求扩大原任务范围。

## 8. 如何确认 subagent 真的生效？

观察 Codex 运行信息：

- 是否实际创建 `refactor-explorer-mini` 或 `refactor-executor-mini`；
- 子 Agent 是否显示 GPT-5.4 mini；
- Explorer 是否保持只读；
- Executor 是否只修改允许范围；
- 主 Agent 是否等待子 Agent 完成；
- GPT-5.5 是否检查真实 `git diff` 和测试结果。

没有看到实际 spawn 时，不要仅因为 Plan 中提到“使用 mini”就认为额度已经转移到 mini。

## 9. 如何继续下一个 Stage？

当前 Stage 通过后：

1. 保存 Stage Plan、Handoff 和 Review；
2. 确认工作区干净；
3. 提交当前 Stage；
4. 新开 GPT-5.5 Session；
5. 使用相同 Prompt，替换 Stage ID 和 TaskList 路径。

# Part B：工作原理

## 10. 推荐执行流程

```text
GPT-5.5 读取需求与代码
→ 按需调用 Explorer mini
→ GPT-5.5 冻结架构和契约
→ 生成 Task Cards
→ Executor mini 分批实现与测试
→ GPT-5.5 检查真实 diff
→ GPT-5.5 做语义 Review
→ Stage 验收
```

## 11. 什么时候使用 Explorer？

适合：

- 不清楚真实调用链；
- 需要全仓搜索旧入口；
- 存在重复 API、Schema 或数据源；
- 删除前需要确认引用；
- 可以拆成互不重叠的只读调查。

不适合：

- 已知只涉及 1～3 个文件；
- 接口和路径已经明确；
- 只是局部修复。

默认不启动 Explorer。只有信息不清楚时才使用。

## 12. 什么时候使用 Executor？

必须先满足：

- 只有一个明确目标；
- 契约已经冻结；
- 允许和禁止修改范围明确；
- 上游依赖已完成；
- 测试命令明确；
- 冲突时有停止条件。

不要给 Executor 发送“完成整个 Stage”这样的宽泛任务。

## 13. 最小 Agent 原则

默认：

```text
已知局部任务：0 Explorer + 1 Executor
未知跨模块任务：1～3 Explorer，之后默认 1 Executor
```

这里的 `0 Explorer` 不代表没有主 Agent，而是由 GPT-5.5 主 Agent直接读取已知文件。

小型任务也可能完全不创建 subagent，由 GPT-5.5 直接完成。

## 14. 并行与串行

可以并行：

- 多个互不重叠的只读调查；
- 前端页面和独立后端测试；
- 不共享公共契约的模块；
- 不修改同一文件的任务。

必须串行：

```text
领域模型
→ 数据库 Migration
→ API Schema
→ 前端类型
→ 集成测试
```

当多个 Agent 会修改同一文件、同一表、同一 API 或同一状态存储时，不要并行。

## 15. Agent 如何同步？

Agent 之间通过以下方式同步：

1. 主 Agent 明确传递 Task Card 和冻结契约；
2. 子 Agent 读取共享工作区；
3. 子 Agent 写入代码并返回结构化结果；
4. Handoff 文件记录变更、测试和风险；
5. 主 Agent 检查 `git status`、`git diff` 和测试输出；
6. 有依赖的下一批任务在上游验收后再启动。

子 Agent 不会自动继承主 Agent 的全部上下文，因此关键决策必须写入 Task Card 或契约文件。

# Part C：可靠性与高级使用

## 16. 状态目录

初始化：

```bash
bash .agents/skills/refactor-orchestrator/scripts/init-refactor-state.sh stage-1
```

默认生成：

```text
.codex/refactor-state/stage-1/
├── stage-plan.md
├── manifest.yaml
├── contracts/
├── tasks/
├── handoffs/
└── reviews/
```

## 17. 每轮产物

```bash
bash .agents/skills/refactor-orchestrator/scripts/capture-round-artifacts.sh TASK_ID ROUND
```

保存：

- Git diff；
- 测试日志；
- Git 状态；
- 执行结果；
- Review 记录。

## 18. 最多三轮修复

```text
第 1 轮：初始实现
第 2 轮：定向修复
第 3 轮：最终受限修复
```

第三轮仍失败后必须停止，交回 GPT-5.5 或用户，避免无限返工和额度消耗。

## 19. Single-controller fallback

以下情况进入回退模式：

- native subagents 不可用；
- 无法确认实际子模型；
- 无法确认 Explorer 权限；
- Codex 版本不支持当前 Custom Agent 配置。

回退时：

- GPT-5.5 保持唯一控制器；
- 继续生成 Plan、契约和 Task Card；
- 输出手工启动 mini Session 的命令；
- 不得声称已经使用 mini subagent。

手工启动示例：

```bash
codex -m gpt-5.4-mini
```

## 20. Review

普通 Stage 可以由当前 GPT-5.5 主 Session Review。

大型或高风险 Stage 建议新开独立 GPT-5.5 Review Session：

```text
Use the refactor-orchestrator skill.

Review the current Stage using:
- source requirement
- Stage plan and approved contracts
- task cards and handoffs
- current git diff
- actual verification results

Classify findings as BLOCKER, HIGH, MEDIUM, or LOW.
Do not accept the Stage only because subagents reported success.
```

# Part D：常见问题

## 21. Skill 没有被加载

检查：

```bash
bash .agents/skills/refactor-orchestrator/scripts/validate-install.sh
```

并确认：

```text
.agents/skills/refactor-orchestrator/SKILL.md
```

位于目标仓库根目录下。

## 22. 没有创建 subagent

先判断任务是否很小。小型任务可以由 GPT-5.5 直接完成。

对于适合委派的任务，Prompt 中必须包含：

```text
Choose and explicitly spawn subagents according to the Skill rules.
Do not rely on implicit delegation.
```

## 23. 子 Agent 模型无法确认

进入 single-controller fallback，不要假设已经使用 GPT-5.4 mini。

## 24. Explorer 修改了文件

检查父 Session 是否使用了 unrestricted full-access/yolo 权限。Custom Agent 的 sandbox 设置可能被运行时权限覆盖。

## 25. 已有 `.codex/config.toml`

不要覆盖整个文件，只合并 `[agents]` 配置。

## 26. 如何控制 Token？

- 不为已知局部任务创建 Explorer；
- 每批默认 1 个 Executor；
- 只向子 Agent 传当前 Task 必需内容；
- 不让多个 Agent 重复扫描全仓；
- 同一 Task 最多三轮；
- 一个 Stage 使用一个新的 GPT-5.5 Session。
